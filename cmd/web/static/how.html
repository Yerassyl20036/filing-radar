How it works

Filing radar reads every new SEC filing within minutes, explains what changed with a source for every claim, and checks each prediction against how the stock actually moved the next day. Below is how it's built, what's live today, and what comes next.

What happens to one filing

  1. 1
    Fetch.

    Every minute the worker reads EDGAR's latest-filings feed and stores each filing once, keyed by its accession number.

    stage 1, next
  2. 2
    Triage.

    Plain rules read the 8-K item numbers, then a model scores how material the filing is. Most filings never reach an LLM.

    stage 2
  3. 3
    Analyst agent.

    For material filings: compare with the company's previous filing and write a short note on what changed.

    stage 3
  4. 4
    Check.

    Every claim must cite a passage that really exists in the filing, or the note isn't published.

    stage 3
  5. 5
    Publish.

    The note appears in the feed with links to the original filing on sec.gov.

    stages 1–3
  6. 6
    Score.

    A Temporal workflow waits until after the next market close, fetches the price move, and checks the prediction. Scores are public.

    stage 4

Live today is stage 0: the three servers, the deploy pipeline, the tunnels and the health checks this page reads.

Data sources

  • EDGAR latest filings — the live feed the worker will poll.
  • EDGAR daily index — every filing of each day, used to repair gaps.
  • SEC developer resources — the access rules: a declared User-Agent and at most 10 requests per second. The radar stays under 1.

Decisions

  • Three servers with 1 GB of RAM each. Go binaries use tens of MB and Temporal's single-binary server under 100 MB, so Kubernetes would cost more than everything else combined.
  • No database port on the internet. The worker reaches Postgres and Temporal through SSH tunnels; each tunnel key may open exactly one port on one machine.
  • A model only where rules can't decide. Item numbers and form types are rules; only filings that might matter go to an LLM.
  • Every claim is checked before it's published. A note whose citation doesn't match the filing's text is retried or dropped.
  • Temporal for waiting, not for everything. The one-minute poll is safe to repeat and needs no workflow engine; the next-day score has to survive restarts, so it gets one.
  • Deploys by hand, from main only. The pipeline ends by proving the worker reached both other servers.
